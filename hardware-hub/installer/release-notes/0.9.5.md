More resilient printing during busy periods:

- Honor Retry-After from PDF HTTP 429/503 responses and preserve the delay in crash-safe failure events.
- Use a separate 90-second PDF download deadline, covering server queue/render time and transfer. Claim, event and heartbeat timeouts remain independent.
- Reject interrupted/truncated downloads, clean up partial PDFs and never dispatch a failed download to a printer.
- Keep renewing the lease while a slow Windows print command is running. Unknown outcomes after a crash still require review and never trigger automatic reprinting.
- Retain one-second idle polling and immediate serial processing of the next ready job.

Deploy the companion RMS update first. It persists Retry-After in the retry schedule, pauses other PDFs for the same register during server backpressure while labels can continue, gives new receipt jobs five total attempts, and separates authenticated Hub PDF quotas (default 60/minute per agent and 180/minute per IP) from manual downloads. PDF renderer concurrency/capacity limits remain active.

The companion update also isolates legacy v1 claim/update endpoints from v2 jobs to prevent ORPHANED_V2_CLAIM errors. No database migration is required for these changes. Older queued jobs retain their existing attempt budget.

Ordinary browser PDF/media traffic no longer counts as failed Hardware Hub authentication on a shared IP. Replayed failure acknowledgements are accepted without consuming an extra attempt or changing the retry schedule; retired attempts still cannot send new events.

Run Setup.exe using the same Windows account as the existing installation. The upgrade preserves encrypted pairing credentials, journal data and printer selection, and configures the new PDF deadline automatically. Verify ASIHJAYA-Hardware-Hub-Setup.sha256.txt before distribution.
